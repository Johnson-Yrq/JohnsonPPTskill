# 默认设计与版式判断

先按已确认的[演讲型或阅读型用途](presentation-modes.md)决定信息密度。下文关于大场景主导、少量说明的常规版式要求适用于演讲型；阅读型按主体版面分区选择 1/2 左右、1/2 上下、1/2 对角双图或 1/4 配图；主体版面不含页头页脚及全宽摘要。先确定配图分区，再用图表、图标、矩阵和文字组织其余内容。有可靠数量数据时可使用 ECharts；不得缩小字号、重复插图或补造指标，放不下则拆页。阅读型内容不可仅放在讲稿中，也不可通过整体缩小来增加密度。

| 项目 | 默认值 |
|---|---|
| 画布 | 1920 × 1080，16:9 |
| 页边距 | 左右 80px；页头起点 48px |
| 页脚 | 底部 30px，顶端横线；Logo 高 34px；公司名 22px |
| 纸色 | `#F7F6F2` |
| 主蓝 / 横线 | `#3B7BC8` / `#9DBDE3` |
| 主文 / 次文 | `#2B3140` / `#5A6373` |
| 浅底板 | `#E7EEF6` 或 `#EDF2F8` |
| 字体 | Noto Sans SC → PingFang SC → Microsoft YaHei → sans-serif |
| 常规标题 / 副标题 | 46px / 25px |
| 内容标题 / 正文 | 29–32px / 24–27px；高密度标注最低约 21px |
| 封面 / 尾页标题 | 82px / 100px，按长度调整 |
| 页码 | 110px，右上，主蓝 |
| 圆角 | 需要时 8px，不做大圆角或胶囊 |

默认品牌“普爱智医 PLANCK AI LABS”，年份取制作年份。标题属于本次大纲，不沿用参考图里的示例标题。用户未指定时不换 Logo、不加入第二种高饱和色、光晕、装饰渐变或蓝图网格。

## 固定不变的部分

| 部分 | 默认形态 | 常见跑偏 |
|---|---|---|
| 封面 | 章节标签留在页头原位；左栏从两行标题（前缀黑 + 主标题蓝）到副标题、承诺句、3 或 6 个浅底关键词、平台标签是一个整体，垂直居中于配图中线；日期固定在页脚上方；右侧大图；右缘层级标注 | 深蓝底、标题居中、无页码、无右侧标注、文案分成两截上下漂 |
| 尾页 | 蓝色 100px 大标题、灰色两行寄语、右侧大场景 | 深蓝底、与封面同图 |
| 页头 | 浅底章节标签 22px、主标题 46px 黑、副标题 25px 灰常规、右上页码 110px 蓝 | 主标题缩到 38px、副标题 32px 加粗当“核心信息”、章节标签去底 |
| 页脚 | 顶端细线、Logo 34px、公司名与年份、右侧方案名 | 改色、缩字 |
| 颜色 | 暖白纸底 + 主蓝，浅底板两种 | 深色页、第二种强调色 |

**封面文案层级**：左栏自上而下是章节标签 → 两行标题 → 一行副标题（对象与范围）→ 一行承诺句（价值）→ 3 或 6 个短词标签 → 可选平台标签。章节标签和其他页一样留在页头，不随正文移动；从标题到平台标签的整块垂直居中于配图中线；日期单独固定在页脚上方。每层一行、各说一件事，`promise` 与 `description` 二选一；字数上限见 deck-format 的 cover 表。大纲的"核心信息""一句说明"往往是副标题的改写，只留一句。

大纲里的“版式规范”“视觉风格”段落只提供结构信息；它们描述的是原作者对某个通用 PPT 的想象，不是对本 Skill 的品牌指令。审查器逐页核对这些形态（`brandOK`），`custom_css` 触碰页头、页脚、封面、尾页选择器会被构建器拒绝。用户明确要求换风格时用 `--allow-restyle`。

## 图形的用途

| 内容 | 适合 | 不适合 |
|---|---|---|
| 独立说明、小标题 | 蓝色标题＋语义图标＋标题下细横线 | 每条说明都套卡片 |
| 并列能力、明确分组 | 少量 8px 圆角浅底矩形 | 随机交替颜色 |
| 实施阶段 | 同尺寸阶段块，阶段/动作/交付分层 | 所有文字变成嵌套标签 |
| 字段、实体、指标因子 | 小型 8px 标签 | 一句话拆成很多标签 |
| 待处理、核查中、已办结等状态 | 放在对应步骤上方的 8px 状态标签 | 混进正文或集中到不对应的页底 |
| 领域清单 | 图标标题、细横线、说明 | 十个大框挤压主图 |
| 封面右侧层级 | 蓝色标题、灰色说明、短细引线 | 实心蓝色标签或大底板 |
| 架构图文字 | 直接放在对应模型下方或层板前缘 | 层名色条、模块框、治理文字底板 |
| 尾页 | 大标题、少量合作文案、大场景 | 联系方式占位、假二维码、密集卖点 |

**无框部分也要有秩序**：蓝色标题、标题下 2px 浅蓝横线、正文 24px、行高约 1.65、组间距约 64px。不要去框后把文字裸散在画面上。不使用左侧彩色竖条装饰。

分组标题默认使用能指代对象、动作或能力的线性图标。封面、尾页、架构直接标注、表格与已有清楚序号的步骤通常无需重复图标；具体省略原因写入设计决策。不能因为某个布局是自定义就省略，也不让同一个通用图标重复代替五种不同含义。图标正常约 33px，与标题对齐；不把 emoji 当统一图标库。

| 页面语义角色 | 默认处理 | 判断依据 |
|---|---|---|
| explanation / domains | open | 普通解释靠蓝色图标标题、横线和间距建立秩序 |
| capabilities / comparison / process | panels | 并列能力、比较项或实施阶段需要归组；真实流程才连接 |
| controls | mixed | 普通输入输出可无框；关键校验、权限或责任组用浅底强调 |
| entities | labels | 独立对象用标签，关系由连线表达 |
| architecture | labels | 直接贴近模型与层板，无任何文字底板 |
| formula | panels | 因子用浅底块，运算符留在块间 |
| cover / closing / table | none | 不自动给普通标题加图标或卡片；专用组件保留其结构 |

这是语义默认值，不是页数配额。遵从已确认要求；适合例外时写清本页理由。

## 版式选择

- `cover`：左侧标题与价值，右侧大图；多层场景可用右侧直接标注。
- `scene`：中间大图＋左右各 1–2 组说明；仅有必要的组用 `panel`，其它 `open`。
- `journey`：上方横向大图＋下方 2–7 列；图片优先，面积阈值以 `--check-plan` 报告的 `image_balance` 为准。真实时间或流程才连接，并列关系不用箭头；同一稿里流程行与能力行统一用信息块或统一无框，不混用。
- `split / triad`：左右图文，1–3 条说明或三段控制，用共享图标标题与信息块。
- `formula / table / relations`：分别保留运算结构、数据列、对象连接，配图辅助解释。
- `architecture`：完整场景＋可编辑叠字；先看图再按坐标标注，不先排文字硬塞图。
- `flow`：顶部 3–5 步，下方左图右侧 2–3 个控制分组；名词解释不额外套框。
- `domains`：中间大图，左右各不超过 5 个领域，横线和间距统一。
- `closing`：致谢或下一步，大幅协作场景，与封面呼应。

版式库是起点，特殊结构可扩展项目 CSS 或新增一两种 `--builder` 版式；不以不合适模板压缩内容，也不把一稿做成八种自造版式加迷你图表。内容页配图通常占内容区三成以上；左右排布时图占宽度约 55–60%。

## 图文融合

按 PNG 中实际可见本体调 `image.zoom / offset_x / offset_y`，别把边缘空白当成图的有效尺寸。主要对象、平台和关键投影要完整，不遮页头页脚。文字靠近对应对象，但不能覆盖关键动作。

架构标注先统一层名轴线与基线，再逐项核对模块中心。错层、缺层、错对象或伪文字必须修图或重生成，不用文字覆盖掩盖错误。

复杂架构以 `reference-design/approved-architecture.jpg` 为参照：模型应占主要内容区，层名靠近层板前缘，模块名贴近对应实物，来源与治理文字跟随实际位置。图和标注作为一个画板等比缩放，不能一个缩放、另一个仍按整页坐标散放。

上图下文使用横向展开的场景，四到七个关键对象要足够分散；实际主体宽度约占图框八成。保留完整人物、主要平台和动作，优先减少空白与重复文案，不以裁去业务对象换取放大。窄图无法兼顾时改左右排版或重新准备横图。

检查图片底色是否接近纸色；四边不能显出一块较暗或较亮的矩形，收图后可用 `match_paper.py --deck deck.json --dry-run` 诊断背景，修正方式见配图流程。默认正常混合，可对单图轻微淡出边缘；全局 multiply 会压暗暖白图片，禁止用它自动解决融合。明显背景或结构错误需修图。

`reference-design/` 的总览、架构、信息块、无框图标、控制页与上图下文示例分别提供对应视觉标准（均为 JPEG 缩图，只看版式与比例），不是可复用的通用业务内容。
