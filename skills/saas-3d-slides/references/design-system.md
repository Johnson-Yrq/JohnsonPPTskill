# 海蓝玻璃 · 整稿视觉规范

先按已确认的[演讲型或阅读型用途](../../scene-html-slides/references/presentation-modes.md)决定信息密度。下文关于大场景主导、少量说明的常规版式要求适用于演讲型；阅读型按主体版面分区选择 1/2 左右、1/2 上下、1/2 对角双图或 1/4 配图；主体版面不含页头页脚及全宽摘要。先确定配图分区，再用图表、图标、矩阵和文字组织其余内容。有可靠数量数据时可使用 ECharts；不得缩小字号、重复插图或补造指标，放不下则拆页。阅读型内容不可仅放在讲稿中，也不可通过整体缩小来增加密度。

本风格以用户确认的 `approved-product-overview.png` 为视觉基准。软件场景的深蓝主屏、精细玻璃边缘、微缩工作站和薄台阶形成图像层次；HTML 中的标题、信息块、图标、页头页脚使用相同的色彩与精细程度。

## 全稿视觉

| 项目 | 规范 |
|---|---|
| 画布与布局 | 共用 1920 × 1080 制作引擎，保留原有 12 种布局，新增阅读型复合布局 |
| 纸色 | 暖白 `#F7F6F2`，与插画背景接近 |
| 主要文字与深色面板 | 海军蓝 `#1D3446` |
| 辅助色 | 灰青 `#477F80`；用于图标、章节与关系符号 |
| 次文 | `#59686E`，保证投影阅读对比度 |
| 金属点缀 | 香槟金 `#BC9B59`，用于短细线与边缘，不用于小号正文 |
| 说明与分组 | 同层级说明默认无框、统一对齐；真实分组才用暖白半透明底、细灰青边框、6px 圆角与轻微阴影 |
| 文字 | Noto Sans SC → PingFang SC → Microsoft YaHei；现代无衬线，沿用离线字体回退 |
| 字号 | 内容标题 46px，副标题 25px；封面主标题 80px，前缀 44px；尾页标题 96px |
| 页码 | 右上 40px 海军蓝，底部短金色细线 |
| 品牌 | 默认保留原 Logo、公司名和 34px Logo 尺寸；不对 Logo 染色 |

全稿只有一个主配色，不为了“科技感”加入光晕、蓝紫渐变、大圆角、霓虹边框或仪表盘背景。玻璃质感主要由配图承担；HTML 只在需要分组的面板上轻量使用透明白底和边缘高光。

## 共用排版如何应用本风格

- `cover`：左文右图；两行标题以小一号灰青前缀搭配海军蓝主标题。关键词是浅灰青标签，平台标签使用深蓝及金色细边。大场景是视觉主体，标签不得遮挡物体。
- `scene`：图居中，左右说明使用深蓝标题、灰青线性图标及细分隔线。重点沿用说明结构，实际独立分组才使用暖白面板。
- `journey`：横向场景在上，能力或阶段在下。普通面板表头浅灰青，必要的重点表头用深蓝；时间或业务流转关系才连接。
- `split / triad`：共用左右图文结构，图像占宽约 55–60%；说明沿统一基线排列，不额外叠加装饰图形。
- `architecture`：以真实层级关系组织三维场景，再定位可编辑文字。深蓝层名、灰青模块名直接贴近对应对象；保持无底板标注，不用大块 HTML 遮盖界面。
- `formula / table / relations`：分别保留运算、比较和对象关系的结构。表头允许深蓝底白字与细金线，关系对象使用浅灰青底。只呈现用户提供的真实内容与数据。
- `flow`：步骤序号用深蓝，控制分组根据语义选择无框或暖白面板；编号与图标不重复表达同一信息。
- `domains`：中心场景配左右开放式领域清单，细线和图标建立顺序。
- `reading`：模块标题贴分区上沿，图标置于浅灰青方块内与标题成组；标题下方的流程、矩阵、图表和来源在分区剩余空间内垂直居中，配图与说明在图区内居中。流程步骤用玻璃面板，矩阵表头深蓝底白字配细金线并隔行淡底，图表单位跟在数值标签后。
- `closing`：海军蓝大标题、少量说明和大幅独立场景，延续封面材质与光照。

## 版式边界

同层级条目的强调保持原有阅读节奏：先使用内容顺序、标题字重及短细线，不为某一项突然增加底色、外框、阴影或内缩。无框 `point` 说明项可写 `"presentation": "open", "emphasis": true`，主题会将标题文字与图标放大约 10%，加强标题字重、改为灰青色，并在原分隔线起点加一段短线。保留文字左对齐、正文大小与条目间距；只放大标题和图标，不整体缩放内容块。放大后复核长标题换行和相邻内容间距。该选项适用于 `scene / split / triad / domains` 及 `formula / table / relations` 的说明区，不按项号自动选中第二项。强调不能让同级内容看起来像不同组件或交互中的选中状态。

面板仍用于边界明确的真实分组或用户要求的卡片布局；不要把 `panel` 当作“重要”的同义词。同层级内容整体采用面板时，卡片之间保持一致的结构与节奏。

共享底座拥有布局几何、内容语义、图片处理、文字编辑、离线保存、打印和播放器行为；本目录 `assets/theme.css` 只定义视觉呈现，必须加载在共享 CSS 之后、项目 CSS 之前。不要复制共享播放器或为本风格另起一套渲染器。

图形配色和实际品牌分别管理。默认品牌未变时保留原 Logo；客户明确提供品牌时按其要求替换。架构、业务流与图表的含义先由大纲确定，再用本风格表达，不能由示例中的金融图表反推产品能力。

## 视觉检查

确认整页标题、页码、细线、图标、标签、面板与配图使用同一组海军蓝／暖白／灰青／少量金色；原来的亮蓝色不得残留为内容强调色。默认 Logo 中的品牌颜色保留。检查大屏与工作站尺度差异、主要平台完整度、图与纸色的接合，以及各布局的标题、脚注与信息块是否溢出。
