# 海蓝玻璃配图

先确认 `presentation_mode`。阅读型按主体版面分区选择 1/2 左右、1/2 上下、1/2 对角双图或 1/4 配图；主体版面不含页头页脚及全宽摘要。先确定配图分区，再用图表、图标、矩阵和文字组织其余内容。有可靠数量数据时可使用 ECharts；不得缩小字号、重复插图或补造指标，放不下则拆页。流程、矩阵、详细标签和真实数据仍用可编辑组件组织。单图用 `image`，`reading` 版式的多图用 `images`（1–3 张），两者互斥。每张图都有独立的 src、alt 与缺图时的 brief；导出清单通过 page、slide_id、image_index 和文件名对应，可分批补齐。已有图继续使用，不重复生图。

风格以 `assets/reference-design/approved-product-overview.png` 为已确认样本，`target-style.png` 为补充目标。生成新场景时可附已确认样本作风格参考，并说明只继承材质、尺度、光照与层级。不要复制参考图中的品牌、金额或业务对象。

## 固定视觉与可变内容

固定的是精细微缩展陈气质：暖白结构主体、海军蓝重点面、灰青玻璃、少量金属细节；小圆角、薄屏与精细倒角；柔和摄影棚光照及明确的前中后层次。柔软感来自材质与光照，不能把设备做成厚重黏土玩具。

本页内容决定对象、数量、动作、关系、密度与画幅。主屏出现时采用**深海军蓝不透明显示面，外包可见的清透玻璃边缘**；软件界面有细密、对齐的屏幕平面结构。流程页可以由连续工作节点主导，架构页可以由真实层级主导，功能页可以采用局部特写；不要求每页都有主屏、人物、台阶或悬浮卡片。

| 页面目标 | 构图与业务表达 |
|---|---|
| 产品总览 | 主要产品对象形成焦点，次要终端及服务按关系围绕；用大小差建立产品层级 |
| 功能介绍 | 放大本页操作对象及处理结果，减少无关背景设备 |
| 业务流程 | 同一对象经过清楚的输入、处理与输出节点；连接与状态来自真实流程 |
| 解决方案架构 | 层数、模块数量、来源与连接遵照大纲，预留模块旁和层板边缘供 HTML 直标 |
| 痛点或对比 | 用分散、受阻、重复处理或处理前后差异解释问题，避免无意义装饰 |
| 真实界面展示 | 采用用户提供或授权取得的产品截图，概念插画只作辅助，不能冒充实际产品 UI |

## `image.brief` 与文字模式

五个字段写本页独有内容；共享导出器会检查缺项、过短简报及跨页复制。英文或中文均可。

| 字段 | 内容 |
|---|---|
| `subject` | 业务对象清单、必要数量、主次尺度与相对位置 |
| `action` | 用户操作或系统处理行为；可以是校验、分派、合并、查询或状态变更，不强制人物 |
| `structure` | 真实层级、输入输出、协作或流转如何由物理关系表达；不能只写“左右排版” |
| `details` | 本页所需设备、模块、界面层级与细节；区分重点、背景和需清洁留白的区域 |
| `composition` | 与图框匹配的比例、视角、展开方向、主体完整性、供可编辑标注使用的位置 |

`image.ratio` 按版式选择：左右图文通常 `4:3` 或 `1:1`，横向流程与上图下文通常 `16:9`，也支持 `3:2 / 3:4`。配图画幅独立于 16:9 演示页；不要把宽流程挤进方形主体。构图应完整包含底座及柔和投影，并给最前方底角约 4% 或足够的画布边距；具体留白以主体不裁切且足够大为准。

`image.ui_text` 控制概念界面中的文字：

- `"demo"`（默认）：沿用已确认示例，只允许在软件屏幕内出现 `Overview`、`Analytics`、`Activity`、`Demo` 这些短标签；无品牌、金额、虚构指标或其它小字。没有屏幕的场景不为满足此模式额外加屏。
- `"none"`：用户要求纯无字配图时使用。不生成字母、数字或伪文字，但保留精细的软件界面布局、细图表、分隔与留白，不能退化成几个大几何块。
- 两种模式都不把页面标题、说明、模块名、图表真实数据或架构标注烘焙进图片。真实截图中的原有界面文字按截图原貌保留；`ui_text` 是生图规则，不是删除真实截图文字的指令。

页面说明与真实数据使用 HTML。结构连接、图表标记与界面小图形可按业务使用，但不能用悬浮文字牌、伪文字或无关线路装饰画面。图表只作概念表达时在讲稿或必要的页面说明中标明其性质。

## 生成、供图与接续

运行共享 `prepare_images.py`，它根据 `style: "saas-3d"` 读取本目录 `assets/image-style.txt`，拼接逐页简报、比例、版式提示和文字模式，输出每条都可独立复制的完整提示词及 `image-manifest.json`。导出目录中的 `style-reference.png` 是同一张已确认样本；生图时随提示词附上，人工供图时一并交付。清单记录 `style`、`style_reference` 与每页 `ui_text`，方便接续时保持一致。

当前环境有直接可调用的内置生图工具时，按其文档逐张生成、查看并保存到项目清单路径，替换图保留原文件并用版本号区分。已有参考图先看后用，不索要 API Key，不擅自改用付费 CLI。需要生成或编辑图像时使用相应图像工具；不要用脚本重绘已确认插画。

没有内置工具时交付 `配图提示词.md` 与清单，明确每页主题、比例和文件名。用户可分批回传或提供 ZIP；按文件名与场景核对映射，不按接收顺序猜页码。已有图标记 `provided`，不要求再次生成。缺图时继续文字与预排，保留准确缺图清单；图片收齐前不把草稿称为成稿。

每张图片都检查对象数量、流程顺序、架构层级、主次尺度、玻璃透明度、海军蓝重心、底座下缘与乱码。主屏应是深色软件显示面，不能误生成为透明屏上漂浮的大型柱状雕塑；次要笔记本与人物应微小、纤薄，不能抢主对象尺度。

把图片放入暖白页面后检查四边融合及整体明暗，不对玻璃、深色屏幕和金属全局使用 multiply 或粗暴提亮。若背景形成明显矩形，使用当前环境要求的图像编辑工具针对背景与取景修正，保留主体材质、投影和原图，逐张复查；不能无条件套用白色模型的背景校准流程。
