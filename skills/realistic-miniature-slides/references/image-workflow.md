# 写实微缩配图流程

先读取本包 `assets/image-style.txt`、`assets/style.json`，查看已确认无文字参考 `assets/reference-design/approved-workflow.png`。路径相对本包根目录。本方向不读取其他包的配图基底。

## 简报与导出

每张需要生成的图提供 `src / alt / ratio / brief`，阅读型可加可编辑 `caption`。`brief` 包括：

1. `subject`：本页具体对象、数量与角色，至少 30 字符。
2. `action`：人在做什么，或系统如何处理；至少 12 字符。
3. `structure`：分组、空间关系、交接或层次，至少 25 字符。
4. `details`：支撑本页信息的设备、材质细节、界面形态等，至少 25 字符。
5. `composition`：比例、35–45° 视角、主体主次、安全边距与配文位置。

不要仅更换标题而复用相同简报，不在所有页面强制四个分区。背景固定暖灰 `#EEEDE8`；人物在场时保留细致五官。流程路径必须对应真实工作关系，架构按实际层级与模块生成，不增加无关办公装饰。

运行 `python3 <shared>/scripts/prepare_images.py <project>/deck.json --out <project>/image-handoff`，检查清单记录 `style: "real-miniature"`、`ui_text: "none"`、独立基底与复制的 `style-reference.png`。导出器仅为缺图产生提示词，已有图先查看、核对语义后复用。

## 无文字策略

本包只提供 `none`，省略 `ui_text` 也采用它。不生成标题、系统名、字幕、区域标识、字母、数字、品牌或伪文字；检查白板、书脊、文件、日历、屏幕及键帽。必要的界面只保留几何卡片、无数字条形与圆环。页面中的标题、系统名、说明和真实数据均用可编辑 HTML。顶部独立图标不是必需的生图元素。

## 生成与检查

有可直接调用的内置生图工具时，使用导出的完整提示词与本包参考生成，遵循工具的图像技能规范；生成前不要把流程变成额外问卷。将产物保存到项目 `images/`，查看人物手部、五官、任务动作、材质、完整边界和残留文字。需要修正时由生图工具编辑，保持已确认方向。

无内置工具时交付清单与提示词，继续可以独立完成的内容和排版；图片仍缺失时准确说明，不静默切到付费 API。不要把 JSON 中的 `src` 当作已存在的素材。

多图阅读页各图对应不同阶段、角色或视角。相同图片换文件名、裁剪成两份不能冒充两张独立配图。场景方向与背景一致，图注在 HTML 中。图片内示意条形图不替代带来源的可编辑 ECharts。

## 底色与占幅

- 供图比例先匹配版面和文字容量。多阶段横向场景可选 2:1、21:9 或 3:1，把对象沿同一阅读方向展开，并给对应说明留出列宽；不将既有模型拉宽，也不靠大块空白凑比例。
- 纸色以清单中的 `paper` 为准（本主题默认 `#EEEDE8`）。查看四边和主体间露出的背景，明显灰色摄影棚渐变交由生图工具修正；轻微淡出仅处理边缘。
- 先用 `python3 <shared>/scripts/match_paper.py <project>/images/03.png --deck <project>/deck.json --dry-run` 读取色差和透明通道。无实际透明像素的棋盘格是图像内容，不能当透明图使用。已有透明图保持原样，复核合成边缘。
- 修图优先使用生图工具。当地工具允许脚本像素校准时，可去掉 `--dry-run`，脚本仅处理预计改动不超过 12 RGB 级的轻微偏差并备份原图；被跳过不等于通过。仅复用已有、已确认均匀纯白底的素材时可用 `image.background_mode: "white-matte"` 做展示映射，具体边界见共享 [配图字段](../../white-blue-slides/references/deck-format.md)。
- 背景融合后检查模型材质、肤色与阴影，再查看 HTML 截图和实际导出 PDF；浏览器中无色块不能代替导出检查。

新生成与重绘都直接使用当前页面纸色：从供图清单读取 `paper`，在提示词中同时写 HEX 与 RGB，并覆盖参考图／原图里不同的底色。换入同纸色的新图后，恢复 `background_mode: "native"`，避免再次染色。不要要求先生成白底再映射；对象之间露出的背景也须同色，阴影仅局部保留。收图后将实际背景与页面对照，仍有明显色块就按同一目标纸色重绘，不把提示词中写了色号视为已经合格。
