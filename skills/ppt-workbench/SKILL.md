# PPT 制作工作台

本入口只负责选择与接入；实际制作遵循所选风格的 Skill。风格决定整稿视觉，类型决定信息密度，两者独立。一个项目记录一种风格，不把不同风格的页面主题或配图规范拼在一起。

## 识别风格与类型

`<shared>` 是同级 `white-blue-slides` 目录。先读取现有项目和当前任务已确认的选择，再运行：

```sh
python3 <shared>/scripts/style_packs.py --list
```

此命令自动发现同级风格包，返回可用的 `id / name / description / skill_file`；用实际清单呈现选项，不把清单写死为两种。若某个包报错，保留其他有效选项；用户指定的包不可用时说明具体缺口，不悄悄换风格。共享套件缺失时先检查本项目的 `skills/white-blue-slides`，确实缺失才说明需要安装。

- 优先级：当前用户明确选择 → 当前项目中基于用户反馈记录的选择 → 询问缺少的维度。直接调用某个风格 Skill 已经是风格选择；沿用现有稿也不重新问卷。软件主题本身不等于选择海蓝玻璃风格。
- 尚缺风格或类型时，在拆页、排版和生图前一次问清缺少的项。风格展示清单中的名称和简短特点；类型解释为“现场讲解的演讲型”或“发给读者独立阅读的阅读型”。两项都缺时合并提问，已明确的项不再问。
- 等待期间可读取大纲、整理事实来源与已有素材；无回复、预选项或示例字段不代表选择。用户明确授权“你来选”时按其目标选择并简短说明，无需重复索取选择。
- 在新项目 `deck.json` 根对象显式写入 `style` 与 `presentation_mode: "speech" / "reading"`。旧稿省略字段时仍可兼容原白色风格／演讲型；这种兼容默认不能用于替用户决定新稿。

## 按选择制作

读取清单中所选风格的 `skill_file`，以它作为实际制作流程；只加载其视觉、配图与验收规范。共享的数据结构、版式、图表、播放器和检查工具由该风格引用，不另起问卷或第二套制作流程。

两种类型的规则见 [用途与信息密度](../white-blue-slides/references/presentation-modes.md)：演讲型围绕结论和少量支撑展开；阅读型把机制、依据与边界留在页面，用图表、流程、矩阵、图标和文字增加信息。阅读型按主体版面（不含页头页脚及全宽摘要）选择 1/2 左右、1/2 上下、1/2 对角双图或 1/4 配图。配图保持作用和面积，图表有可靠数据才采用 [离线 ECharts](../white-blue-slides/references/charts.md)。

最终按用户要求交付并完成对应验证。本套件的构建器生成单文件 HTML；如明确要求 PPTX，保留风格和类型选择，转入能生成 PPTX 的可用制作流程，不将 HTML 当作替代交付物。

## 持续新增风格

用户要求新增或迭代风格时，按 [新增独立风格包](../white-blue-slides/references/adding-styles.md) 创建同级包。每个包独立维护主题、配图提示词、参考图与检查规范；无需修改本入口的选项或复制共享脚本。已确认的设计方向直接采用，尚未确认的新方向先做样例供用户选择。更新 Skill、验证套件或制作类型对比示例时，不启动真实演示稿的用途问卷。
